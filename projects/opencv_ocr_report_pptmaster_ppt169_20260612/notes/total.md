# 01_cover

本页说明项目主题和报告定位。重点是让读者先看到项目不是单纯 OCR 调用，而是围绕攻略截图到结构化数据的一条处理链路。

# 02_summary_keywords

本页给出摘要层面的结论。项目的核心贡献是把复杂截图逐步拆成可识别的小单元，并通过后处理生成可供自动化系统使用的数据。

# 03_background_problem

本页说明需求来源。游戏攻略截图对玩家可读，但对自动化系统不可直接使用，因此需要把表格内容转成稳定字段。

# 04_requirement_layers

本页把需求拆成图像层、结构层和语义层。三层分别对应表格定位、行列恢复和动作字段规范化。

# 05_overall_design

本页展示总体设计。系统先改善图像质量，再定位表格区域，随后恢复网格结构，最后做 OCR 和业务后处理。

# 06_pipeline

本页从流程角度解释系统如何逐步缩小 OCR 的问题规模。OCR 不再面对整张复杂截图，而是处理经过切分的单元格。

# 07_preprocessing

本页说明预处理的作用与边界。灰度化、降噪和二值化能提升图像质量，但不能单独解决表格结构恢复问题。

# 08_grid_recovery

本页强调区域定位和网格恢复的重要性。系统通过规则网格主体、横竖线和交点关系推断单元格边界。

# 09_cell_ocr_parser

本页说明复杂单元格的处理。动作符号、多行说明和低置信结果需要专门解析，而不是当成普通文本直接接受。

# 10_postprocess

本页说明后处理为什么必要。自动化系统最终需要的是回合、动作、说明等字段清楚的数据，而不是一段 OCR 文本。

# 11_output_debuggability

本页展示输出形态和调试价值。中间结果可以帮助判断问题来自预处理、定位、网格恢复、OCR 还是后处理。

# 12_iteration_timeline

本页还原项目演进过程。方案不是一次性设计完成，而是在云端 OCR、整图 OCR、预处理和结构恢复之间逐步收敛。

# 13_current_capabilities

本页归纳当前方案特点。它是面向固定结构攻略表格的本地处理闭环，优势在于成本可控、链路完整和便于调试。

# 14_limits_next

本页如实呈现不足。后续改进重点包括截图风格泛化、动作符号专门识别、参数稳定性和量化评估。

# 15_conclusion

本页收束项目价值。项目能够体现图像处理知识在真实业务问题中的应用过程，核心主线是表格结构恢复。
