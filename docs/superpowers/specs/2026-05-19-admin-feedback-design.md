# 管理员反馈管理模块设计

## 背景
- 当前项目已经有普通用户反馈页：`app/src/main/java/com/example/yuanassist/ui/FeedbackCenterActivity.kt`
- 当前 `issue_feedback` App 侧模型字段已确认包含：
  - `deviceId`
  - `user`
  - `description`
  - `logContent`
  - `imageUrls`
  - `reply`
  - `status`
- 当前普通反馈能力只覆盖“提交反馈 + 查看当前设备自己的反馈记录”，不支持管理员查看全表或写入官方回复。

## 目标
- 在 `Mine` 页新增一个仅管理员设备可见的“反馈管理”入口。
- 进入后可在手机上查看 `issue_feedback` 全表反馈。
- 每条反馈至少可查看：
  - 提交时间
  - 反馈设备 ID
  - 问题描述
  - 图片
  - 当前回复状态
  - 现有官方回复
- 管理员可以对单条反馈填写一条官方回复。
- 回复成功后，写回 `issue_feedback.reply`，并把 `issue_feedback.status` 更新为“已回复”。

## 非目标
- 不改首页现有“问题反馈”入口。
- 不把普通用户反馈页改造成管理员/普通用户双模式页。
- 不做多轮对话，不新增“反馈会话”能力。
- 不在本次需求中扩展为基于账号角色的完整后台权限体系。

## 管理员边界
- 管理员设备固定为：`815e9c7c33fa662e`
- 前端仅在当前设备 ID 等于该值时展示“反馈管理”入口。
- 后端接口也必须再次校验 `deviceId`，不能只依赖前端隐藏入口。

## 推荐方案
采用“`Mine` 页新增独立入口 + 新建独立管理页”的方案。

原因：
- 不影响首页现有反馈入口与普通用户路径。
- 管理页职责清晰，避免和 `FeedbackCenterActivity` 的普通反馈逻辑缠在一起。
- 后续若要增加筛选、仅看待回复、复制设备 ID 等能力，扩展空间更干净。

## 入口与导航设计
### `Mine` 页入口
- 扩展 `MineTabActions`，新增打开“反馈管理”页面的 action。
- 在 `MineTabScreen` 的入口列表中新增一个独立项，例如“反馈管理”。
- 该入口只在管理员设备下显示，普通设备不显示，占位也不保留。

### 页面跳转
- 新建单独页面，例如 `FeedbackAdminActivity`。
- 从 `MainActivity` 的 `MineTabActions` 负责跳转。
- 不修改 `HomeTabScreen` 中现有 `onOpenFeedback` 的含义和行为。

## 页面设计
### 整体风格
- 复用现有子页面体系：
  - `SubpageScaffold`
  - `SubpageSectionCard`
  - `SubpageBadge`
  - 现有暖色纸感、Serif 标题、金棕描边风格
- 不引入新的后台风或管理台风格。

### 页面结构
页面建议分为两段：

1. 顶部说明区
- 标题：`反馈管理`
- 副标题：如“全表阅览 · 官方回复”
- 可展示当前管理员设备 ID，帮助确认当前模式。

2. 反馈列表区
- 按时间倒序展示反馈记录。
- 每条卡片展示：
  - 创建时间
  - 状态徽标：`待回复` / `已回复`
  - 反馈设备 ID
  - 问题描述
  - 图片首张预览
  - 现有回复
  - 回复输入框
  - 提交回复按钮

### 交互细节
- 已有回复的记录也允许再次覆盖提交，以便修订官方回复。
- 图片先沿用现有 `imageUrls` 的首张图展示逻辑。
- 若 `imageUrls` 存多张且为逗号分隔，本次先只展示首张，避免扩 scope。
- 若 `description` 为空，按现有普通反馈页习惯展示兜底文案。
- 回复按钮提交中时禁用，避免重复点击。

## 数据与接口设计
### 当前已知数据模型
基于 App 侧模型，当前设计默认 `issue_feedback` 已具备管理员回复所需字段：
- `reply: String`
- `status: Int`

本次不新增回复表，不改为多轮消息结构。

### 前端仓储层改动
在 `SupabaseRepository` 中新增管理员接口封装：

1. `listFeedbackForAdmin(...)`
- 目标：返回 `issue_feedback` 全表记录，而不是当前设备自己的反馈。
- 请求体需包含当前设备 ID，供后端校验管理员权限。

2. `replyFeedbackAsAdmin(...)`
- 入参至少包含：
  - 当前设备 ID
  - 目标反馈记录 ID
  - 回复文本
- 后端成功后返回更新后的 `issue_feedback` 记录，或返回成功标记。

### 后端动作
现有 edge function 路由是统一 `action` 风格，请沿用现有模式补两个 action：

1. `list-feedback-admin`
- 校验 `deviceId == 815e9c7c33fa662e`
- 返回全表反馈，按创建时间倒序

2. `reply-feedback-admin`
- 校验 `deviceId == 815e9c7c33fa662e`
- 根据反馈记录 ID 更新：
  - `reply`
  - `status = 1`
- 返回更新后的记录或标准成功结果

## 错误处理
- 非管理员设备调用管理员接口时：
  - 前端不显示入口
  - 后端仍返回无权限错误
- 列表加载失败：
  - 页面展示空状态卡片和错误提示
- 回复内容为空：
  - 前端直接阻止提交并提示先填写回复
- 回复提交失败：
  - Toast 或页面提示错误信息
  - 保留输入框内容，方便重试
- 图片 URL 异常：
  - 不阻塞卡片展示，图片区域直接隐藏

## 实现边界与兼容性
- 普通用户反馈页 `FeedbackCenterActivity` 保持原职责：
  - 提交反馈
  - 查看自己的历史反馈
- 管理员反馈管理页单独处理全表查看与回复。
- 这样即使后续普通反馈页继续调整，也不会把管理员逻辑带进去。

## 安全约束
- 本次仅做设备 ID 级管理员控制，属于轻量权限方案。
- 由于设备 ID 存在被伪造理论风险，后续若要提升安全性，应升级为：
  - 用户角色字段
  - 服务端角色校验
  - 更严格的认证链路
- 但本次先不扩 scope。

## 验证范围
本次实现完成后，至少验证以下场景：
- 管理员设备在 `Mine` 页可见“反馈管理”入口。
- 非管理员设备看不到该入口。
- 管理员可加载全表反馈。
- 管理员可看到问题描述、首张图片、当前回复状态。
- 管理员填写单条回复后，记录状态变为已回复。
- 普通首页“问题反馈”入口与原有用户提反馈流程不受影响。

## 当前假设
- 当前会话未直接读取到在线 Supabase 表结构，设计基于现有 Android 模型和仓储调用方式展开。
- 设计默认服务端 `issue_feedback` 实际字段与 App 侧模型一致，并且记录主键可用于更新单条反馈。
- 若后端实际字段名或返回结构不同，实现时以真实接口为准微调，但不改变本设计的交互边界与职责拆分。
