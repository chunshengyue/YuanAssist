# 星石本地 OCR 行距推导设计

## 背景
- 当前星石散图本地 OCR 的痛点已经从“检测框过少”转成“行数和最后一行容易漏”。
- 用户已明确要求：不要再只靠整图候选行聚类去猜所有行，而是先 OCR 出前两条，再用它们推导整图剩余行中心。
- 同时，单行 OCR 需要和四等分 OCR 比选，若数量打平则优先四等分结果。

## 目标
- 用 OCR 结果推导整张散图的行中心和行数。
- 优先依靠“前两条等级行”和“前两条名字行”确定对应行间距。
- 对每个推导出的行，分别执行：
  - `整行 OCR`
  - `4 等分 OCR`
  - 保留识别数量更多的一版，打平保留 `4 等分`
- 让最后一行不再因为检测框不足而漏掉。

## 主流程
1. 在散图上用 Paddle 先做一次文字识别，收集候选文字行。
2. 先 OCR 出前两条等级行和前两条名字行。
3. 用这两条的`文字中心`求出对应行间距：
   - 名字行间距
   - 等级行间距
4. 按对应间距推导整图所有名字行和等级行的中心位置。
5. 对每一个行中心：
   - 横向拉满宽度
   - 取合适高度裁成整条字行
   - 先做整行 OCR
   - 再做四等分 OCR
   - 保留识别数量更多的一版
   - 数量打平则保留四等分
6. 把所有行的识别结果组装成 `MyStoneRow/MyStoneCell`。

## 关键规则
### 1. 前两条必须靠 OCR
- 不允许用固定偏移直接猜出第一、第二条。
- 第一、第二条必须来自真实 OCR 识别结果。

### 2. 行距优先使用名字行间距
- 通过前两条名字行之间的间距来确定名字行序列更稳。
- 等级行可以独立计算自己的间距。
- 两套行序列可以独立维护，也可以按行配对，但都不能直接用固定偏移偷算。

### 3. 整行 vs 四等分
- 每条行同时做两套识别：
  - 整行 OCR
  - 四等分 OCR
- 识别数量更多的一版优先保留。
- 如果数量相同，保留四等分。

## 调试与输出
- 记录前两条 OCR 到的名字行/等级行文本与中心点。
- 记录推导出的行间距。
- 记录每条行的两种识别结果数量。
- 记录最终采用的是整行还是四等分。

- 四等分结果在数量打平时优先保留。
