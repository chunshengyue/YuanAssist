# BBQ 替换素材气泡选择设计

## 目标

把 `TestActivity` 里烧烤需求素材的一键替换改成更好操作的链路：

- 只针对 BBQ 需求素材生效
- 点击“替换素材”后先选择 `气泡1 / 气泡2 / 气泡3`
- 进入所选气泡的局部放大预览
- 红框保持实际裁剪尺寸 `40x40`
- 用户拖动的是放大后的预览框，但最终保存的仍是原图里的 `40x40` 素材

## 设计

### 1. 入口分流

`startTemplateReplacementFlow()` 保留原有通用逻辑，但当当前任务是 BBQ 且当前素材属于需求素材时，改为先弹出气泡选择框，不再直接走通用 ROI 来源选择。

### 2. 气泡 ROI 来源

三个气泡直接复用烧烤模式已有的固定坐标：

- 气泡1：`250x250` ROI，中心点使用现有 `BBQ_BUBBLE_1_*`
- 气泡2：`250x250` ROI，中心点使用现有 `BBQ_BUBBLE_2_*`
- 气泡3：`250x250` ROI，中心点使用现有 `BBQ_BUBBLE_3_*`

这样替换素材与运行时识别使用同一组气泡范围，不引入新的坐标来源。

### 3. 预览放大方式

现有 `ReplacementPreviewView` 新增“显示源区域”概念：

- 默认仍显示整张截图，兼容其他替换流程
- BBQ 气泡替换时只显示所选气泡 ROI
- 触摸坐标仍映射回原图坐标，保证最终截取结果仍是原图的 `40x40`

### 4. 逻辑校验

完整链路：

1. 用户在测试页选择 BBQ 需求素材
2. 点击“替换素材”
3. 弹框选择气泡1/2/3
4. 预览只显示对应气泡 ROI，并按控件尺寸等比例放大
5. 用户拖动固定 `40x40` 红框
6. 保存时仍从原图中裁出 `40x40` 并写入 override

链路中“显示放大”和“实际裁剪”分离，避免把放大后的像素误存成素材。
